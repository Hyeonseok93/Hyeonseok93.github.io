# 서론

> **"Day 45에서 ARGUS CI/CD와 실배포 스모크까지 끝낸 뒤, 오늘은 최종 산출물 제출을 마쳤습니다. 수행계획서부터 시연 영상·발표자료까지 패키지를 올렸고, 이제 남은 건 PPT 소수정과 최종 발표 준비뿐입니다. 일상 개발일지는 여기서 멈추고, 최종 발표 뒤에 마무리 소감으로 오프라인 세션 업로드를 마무리하겠습니다."**
>
> 기능을 더 붙이는 날이 아니라, **제출로 일정을 마무리하고 일지 리듬을 한 번 멈추는 날**입니다.

# 1. 오늘 작업의 방향

오늘은 Day 45에 적어 둔 **최종 산출물 제출**을 실제로 끝내는 날이었습니다.

- 제출 체크리스트에 맞춰 산출물 패키지를 모아 제출했습니다.
- GitHub URL·시연 영상·발표자료처럼 “동작·근거가 남는” 항목도 같이 올렸습니다.
- PPT는 제출본 기준으로 두고, 발표 전 **소소한 수정**만 남겼습니다.
- 일상 개발일지는 Day 46을 끝으로 **잠시 멈추고**, 최종 발표 뒤 **마무리 소감** 한 편으로 오프라인 세션 업로드를 마무리하기로 했습니다.

Day 1부터 이어 온 일지는 진단·인프라·자동화 과정을 남기는 쪽이었습니다. 제출이 끝난 지금은 구현 기록을 더 쌓기보다, 발표에 집중한 뒤 소감으로 매듭짓는 편이 맞다고 봤습니다.

# 2. 최종 산출물 — 무엇을 올렸는지

제출 항목은 아래와 같습니다. 각 문서를 다시 풀어 쓰기보다, **패키지에 왜 들어갔는지**만 짧게 남깁니다.

1. **수행계획서** — 범위·일정·역할의 기준선
2. **요구사항 정의서** — 진단·보고·인프라 요구를 문서로 고정
3. **WBS** — 작업 분해와 진척을 추적할 단위
4. **인프라 구성도** — Onde / Argus AWS 구성을 한눈에
5. **클라우드 사용계획서** — 리전·서비스·비용·보안 전제
6. **데일리 스크럼(회의록)** — 의사결정과 이슈 이력
7. **GitHub URL** — 코드·IaC·파이프라인의 근거
8. **멘토링 일지** — 피드백과 반영 기록
9. **시연 영상** — 말로만 끝내지 않는 동작 증적
10. **최종 발표자료(PPT)** — 발표 스토리의 제출본 (이후 소수정만)

문서·회의록이 “과정”을 남긴다면, GitHub·시연·PPT는 “결과물이 실제로 돌아가는지 / 어떻게 말할 것인지”를 남깁니다. Day 43–45에서 올린 인프라·CI/CD·스모크가 7·9번과 바로 이어집니다.

# 3. 아직 남은 것

제출은 끝났지만, 일정 전체가 끝난 것은 아닙니다.

- **PPT 소소한 수정** — 문구·장표 순서·시연 타이밍 정리
- **최종 발표 준비** — 리허설, 데모 계정·URL·롤백 포인트 점검

개발일지에 새로운 구현 기록을 더 쌓기보다, 앞으로는 **발표에 집중**하는 쪽으로 가닥을 잡았습니다.

# 4. 발표 전, 일지를 한 번 멈추며

짧게만 남깁니다.

첫째, Day 1에 잡은 과제는 **클라우드 위의 취약점 진단·모의해킹**이었고, EMR 타깃에서 **진단 SaaS**로 방향을 틀며 개발 트랙과 인프라 트랙을 나눴습니다. 이후 블로그에 실제로 쌓인 축은 **온데(Onde)를 대상으로 한 수동 진단·이행 점검**과, 그 경험을 제품화한 **아르고스(Argus) 자동 진단**이었습니다.

둘째, 중반은 가이드라인 기준 진단·멘토링·중간 발표와 Argus 모듈·리포트 쪽이 중심이었고, Day 40 전후부터는 로컬 Compose를 **AWS 프라이빗 서브넷 배포**로 옮기는 설계로 넘어갔습니다. Day 43–45는 그 설계를 Terraform·ECR·SSM CD·`rookies-argus.click` 스모크까지 밀어, 제출물의 인프라 구성도·GitHub·시연과 맞춘 구간입니다.

셋째, 이번 제출은 Day 1에 뼈대만 있던 수행계획·요구사항을, 진단 증적·회의록·멘토링 일지·코드·시연·PPT까지 넣은 **최종 패키지로 모아 올린 것**이었습니다. 일상 개발일지는 **Day 46에서 잠시 멈추고**, 최종 발표를 한 뒤에 **마무리 소감**을 마지막으로 올려 오프라인 세션 업로드를 마무리하도록 하겠습니다.
